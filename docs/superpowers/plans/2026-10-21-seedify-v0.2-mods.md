# seedify v0.2 模块化建造 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按已审定的 mod 设计 v2，把 seedify 从单技能流水改造成七模块（生成族 M1–M5 + 读取族 M6/M7）+ 编排器 + 8 命令的 v0.2.0 插件。

**Architecture:** 纯技能文本插件（Markdown + YAML frontmatter，零代码依赖）。每个 mod = 独立 `skills/<name>/SKILL.md` + `references/charter.md` 逐字节副本，单独可调用、单独可改进；编排器 `skills/seedify/` 只做串链、边界判断与交付即止；命令为薄封装不重复逻辑；seed-reviewer 升级为 M7 的独立上下文执行体（适配器探测到才派发）。

**Tech Stack:** Markdown/YAML 技能文本；bash（复制/校验/打包）；python3 + PyYAML（frontmatter 严格校验）；`claude plugin validate`（清单体检）；行为护栏 T1–T27（会话实测）。

**Spec:** `docs/seedify-mod-design-v1.md`（v2 已审定，下称"设计"）+ `docs/prompt-optimization-charter.md`（总纲 v4，最高指导，**原文不得改动**）。执行者须两份都读。

## Global Constraints

（每条任务的验收隐含本节全部要求；值均抄自总纲/设计/项目记忆，不得自由发挥）

- 总纲 v4 **原文不动**；每 mod 的 `references/charter.md` 均为 `seedify/skills/seedify/references/charter.md` 的**逐字节副本**（校验：sha256 一致）。
- 正例、反例一律不进技能上下文与用例文本；护栏用例只写「输入特征 → 通过标准」（裁定#3、设计 §13）。
- 生成链交付物只有一件：提示词本身（代码块）。改动对照、改动依据、整理过程、总结段、来源、把握度等排练期元信息一律不出（裁定#5、T5/T15/T19）。
- 提问一律开放问法，禁填空模板；有疑必问、先问后写、不限次数（裁定#2/#6）。
- 种子自然生成：目标/硬边界/验收三要素仅作提示不作栏位，说到多少写多少；不写实施方法（流程/步骤/角色/示例/格式），用户明确要求的除外（裁定#1）。
- 评分红线（设计 §4.2 M7）：评分只度量纲领纪律符合度；报告必含原句「只度量纲领纪律符合度，不预测实践效果」；分数不得作为优化目标或交付门槛；不得因「详细/结构完整/有示例」加分；合格 = 纲领病灶项全部通过。
- Hooks/MCP/Settings = 0；不引外部依赖；不执行脚本、不调外部服务（M4 的可选网络检索仅在用户启用且允许时发生，无则降级不阻塞）。
- 路径纪律：agent 内一律 `${CLAUDE_PLUGIN_ROOT}/...`；技能内引用自家 `references/...` 相对路径；**本机绝对路径不进任何可分发文件**。
- YAML frontmatter 中含「冒号+空格」的中文描述必须用块标量 `description: |`；每次改 frontmatter 后用 `python -c "import yaml; yaml.safe_load(...)"` 对 `---` 之间内容严格自测。
- `allowed-tools` 兼容两代派发工具名：派发型命令/代理用 `Read, Task, Agent`；直通型命令/技能用 `Read`。
- 版本 0.2.0 双处同步：`seedify/.claude-plugin/plugin.json` 与每个 SKILL.md 的 `version` 字段。
- 发布门禁：`claude plugin validate D:/AIGC/Seedify` 必须通过。
- 护栏编号沿用设计 §10：T1–T21 继承既有语义，T22–T27 为读取族与评分新增；用例归属模块见 Task 1 映射表。

## Review Focus

（最可能咬人的五类失败模式，每条注明钉住它的测试）

1. **frontmatter 解析失败**（中文描述里「冒号+空格」把 YAML 弄坏，sed 自测漏检）——钉在 Task 2–10 各自的 frontmatter 校验步骤（python yaml.safe_load 严格解析）。
2. **charter 副本漂移**（某个 mod 的副本与总纲不一致，产出违背纲领却查不出）——钉在 Task 11 的 sha256 一致性核验步骤。
3. **评分越线**（分数变目标/门槛、为「详细」加分、漏「不预测实践效果」声明）——钉在 Task 8 的 T23/T24 用例运行。
4. **内部产物泄漏进交付物**（对照/依据/来源/把握度/体检报告混进提示词代码块）——钉在 Task 9 的 T5/T19/T26 与 Task 5 的 T15 用例运行。
5. **可分发文件夹带本机绝对路径**（`${CLAUDE_PLUGIN_ROOT}` 未解析或写死 D:\ 路径）——钉在 Task 11 的全量 grep 核验步骤。
