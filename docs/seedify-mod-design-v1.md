# seedify 模块化（mod 化）设计文档

**v2 · 2026-10-21 · 已审定**（2026-10-21 晚用户审定通过；晚间增补：读取族 M6/M7 两模块）
**设计依据**：`prompt-optimization-charter.md`（总纲 v4，**用户定稿，原文不动**）+ `seedify-design-v1.md`（v6，已实现的 v0.1.0）+ 用户 2026-10-21 口述裁定（本文件 §3 记录，晚间增补见 §3.1）+ 外部调研（§14 来源）。
**一句话**：把 seedify 从"单技能流水"改造成"模块化的提示词排练室"——生成族五模块（表达整理、需求澄清、种子生成、工具挑选、提示词装配）与读取族两模块（提示词分析、提示词检查）共七个独立模块，可单用、可串链、可分开改进；生成族产出**裹着 harness 脚手架的种子提示词**，服务两个时刻：开项目前的预演，和中途迷路时的头脑风暴重造；读取族对任意现成提示词做意图解读与质量体检。

---

## 1. 背景与动机（why）

1. **v1 实际使用痛点**：产出提示词过于精简、缺乏结构化内容、不够完善（用户 10-21 反馈）——纯种子裸交付，在"全新会话开场"场景下信息不足。
2. **开场提示词至关重要**：用户开新项目/新会话时粘入的第一条提示词决定项目起点质量；seedify 的定位是**开工前的排练室**——先预演、预热，定稿后再正式开工。
3. **两个使用时刻**：
   - 时刻 A·开项目：搭建开场提示词与开场环境，把用户最初的想法和思路捋出来，少走弯路；
   - 时刻 B·中途迷路：项目走一步看一步、思绪乱掉时，通过头脑风暴找出方向与 idea、引导选择，再把谈出来的东西沉淀回提示词。
4. **架构耦合问题**：v1 把表达整理与种子生成绑在一个技能里，不能单独调用、不能分开改进——本次拆开。
5. **读取族需求（10-21 晚用户提出）**：需要「提示词分析」（解析提示词意图、搞清用户需求与想做的事）与「提示词检查」（对任意提示词做质量检查、合格判定与评分）；二者面向任意现成提示词（用户自带或已装配），与生成链并列成第二条能力轴（读取族）。

## 2. 目标 / 非目标 / 反目标

**做**：
- 五个模块各自独立：单独调用、分开改进、互不拖累；
- 逐层递进的命令链：单模块 → 组合子链 → 一键全链路；
- 需求澄清（追问 + 头脑风暴 + 流程体检）；
- 工具挑选（结构化推荐清单）；
- 提示词装配（种子内核 + harness 脚手架 → 完整结构化提示词）；
- 读取族两模块：提示词分析（意图解读）+ 提示词检查（分项通过 + 纪律符合度总结分 + 合格判定，升级 /seed-check）。

**不做**：
- 不改总纲 v4 原文（含增补脚手架条款一事，见 §8）；
- 不做 L2 循环进化 / L3 经验沉淀机制（继续归平台循环，总纲四）；
- 不设效果验收指标（用户裁定：按最终效果走一步看一步）；
- 不引入硬性外部依赖（Hooks/MCP/Settings 维持 0）。

**反目标（做成即失败）**：
- 三大病灶复发：臆造用户没说的内容、角色堆砌、把软细节（流程/步骤/示例/格式）当硬约束写死；
- 装配变成蓝图：脚手架≠施工图，Agent 的自主研究、自主规划、自我修正空间被预设夺走；
- 硬依赖第三方 grill 技能或外部服务才能跑起来；
- 交付物不再是"只有提示词本身"（改动对照/整理依据/整理过程/总结四类内部检查项泄漏进交付物；工具推荐的来源、把握度等排练期元信息同样留在对话）。
- 评分被当成优化目标或交付门槛（元指标病灶复发），或用通用「好提示词」标准（详细、结构完整、有示例）为病灶加分。

## 3. 本轮用户裁定记录（2026-10-21，对话定稿）

| 事项 | 裁定 |
|---|---|
| 种子与脚手架 | 提示词**仍是种子**；装配层是 **harness 式脚手架**（工具环境、已确认结论、生长方向引导），**不是蓝图**——建筑怎么盖留给 Agent 在循环里自己定 |
| 用户给出的流程 | 不写死、不臆造；但要**体检评估**其合理性与对项目的正负面影响，把建议说给用户听（对话内），用户改后定稿 |
| 两个使用时刻 | ① 开项目：搭开场提示词 + 开场环境；② 中途迷路：头脑风暴找方向 → 重造提示词 |
| 交付边界 | 最终交付物只有提示词本身（一串完整的、结构化的提示词），原样粘进新会话/项目使用 |
| 验收标准 | **暂不设定**；改没改坏看最终效果，走一步看一步 |
| 第三方追问技能 | 可集成 grill-me 等作为单独 mod（具体接法由我方在 §9 定） |
| 总纲地位 | 总纲 v4 原文不动；"脚手架"作为本次裁定记入本设计文档（§8），是否升入总纲 v5 由用户日后亲定 |

### 3.1 增补裁定（2026-10-21 晚间，提示词分析/检查两模块）

| 事项 | 裁定 |
|---|---|
| 提示词分析形态 | **合并形态的意图解读模块**：输入任意表达（嘈杂口语/草稿/现成提示词），产出意图理解——想做什么、要什么、想表达什么；对象为现成提示词时输出「这段提示词在要什么」 |
| 评分制式 | **总结分 + 分项通过**：纲领各项逐项通过/不通过打底，另给纪律符合度总结分；报告必附声明「只度量纲领纪律符合度，不预测实践效果」 |
| 体检入口 | **升级 /seed-check**（合格判定与评分并入），不另立门户 |
| 检查形态 | **mod 主入口 + 适配独立上下文**：做成 mod 随 cowork 分发；探测到可派发子代理则走独立上下文（沿用 grill 适配器模式，探测到才用） |
| 链内质检 | **不自动，点名才查**：/seedify 交付仍是纯提示词（T19 不动），质检由 /seed-check 单独触发 |

## 4. 模块设计（b：怎样设计 mod）

**mod = 一个自治能力单元**：独立 SKILL.md + 自带 references/，有自己的输入/输出契约、内部纪律、禁止事项；单独可调用、单独可改进（改一个不动别人）。编排器与命令是薄层，逻辑全部住在 mod 里。

### 4.1 模块清单（七模块 + 编排器）

| mod | 目录 | 职责 | 来源 |
|---|---|---|---|
| **M1 表达整理** | `skills/seed-express/` | 语音转写文本纠错、去赘、消歧、保真归一（可回指 + 零丢失） | v1 表达整理规则独立成体 |
| **M2 需求澄清** | `skills/seed-clarify/` | 三模式：**追问**（倒逼梳理思路）、**头脑风暴**（找方向与 idea）、**流程体检**（评估用户流程+给建议） | 新增；方法借鉴 grill 系列（§9）（2026-10-22 起由 docs/superpowers/specs/2026-10-22-m2-grill-tospec-design.md 取代：两席制） |
| **M3 种子生成** | `skills/seed-gen/` | 从干净意图自主成文种子：目标/硬边界/验收仅作提示，不写实施方法 | v1 种子规则独立成体 |
| **M4 工具挑选** | `skills/seed-tools/` | 按澄清后的需求挑选插件/skill/MCP 连接器，出结构化推荐清单（搭环境用） | 新增 |

| **M6 提示词分析** | `skills/seed-analyze/` | 意图解读：任意表达/现成提示词 → 意图理解（读取族） | 新增（10-21 晚裁定） |
| **M7 提示词检查** | `skills/seed-check/` | 质检评分：分项通过 + 纪律符合度总结分 + 合格判定（读取族） | seed-reviewer/seed-check 升级（10-21 晚裁定） |

### 4.2 各模块契约要点

**M1 表达整理**（继承 v1 §6 全部规则）
- 输入：任意含噪声的自然语言文本（语音转写为主）；输出：干净表达（单独调用时即交付物；链路内作为中间产物）。
- 纪律：纠错有据（术语/代码标识符保原文）、信息零丢失、改口以最终说法为准、消歧优先于臆断、可回指。

**M2 需求澄清**（本设计核心新增）
- 输入：整理后的表达（或直接现状描述）；输出（对话内）：捋清的需求/思路/方法论 + **已确认结论清单**（供装配）。
- 三模式按需启用：
  - **追问**：输入含糊、思路不清时，开放式、层层递进地发问（一次一个主题），倒逼把需求、思路、方法论、方案捋清；禁填空模板（裁定#2）；不限次数（裁定#6）；
  - **头脑风暴**：用户迷路/走一步看一步时，主动抛出候选方向与 idea 供挑选（时刻 B 的主入口）；候选是对话内选项，**不直接写进交付物**；
  - **流程体检**：用户已给出流程/步骤时，评估其合理性与正负面影响，建议说在对话里；用户流程本身可回指保留，评估意见不进提示词。
- 借鉴外部方法（不照搬、不硬依赖）：grill-me 的"无情追问打磨计划"、interview-me 的"一问一答直到意图清晰"、grill-with-docs 的"边问边沉淀已定决策"。

**M3 种子生成**（继承 v1 §7 全部规则）
- 三要素仅作提示，说到多少写多少；不写实施方法（流程/步骤/角色/示例/格式），用户明确要求的除外；自然生成不套格式；缺项/存疑回到 M2 先问。

**M4 工具挑选**
- 输入：澄清后的需求（想搭什么环境：开发/写作/创造）；输出分两版：**对话版清单**（名称 / 类型（插件·skill·MCP）/ 为什么是它 / 如何启用 / 来源 / 把握度——排练期供你判断取舍）与**交付版清单**（名称 / 类型 / 为什么是它 / 如何启用一句话——供装配进【环境与工具】）。
- 信息源分层（零硬依赖）：① 本地已装的 skills/plugins/MCP 清单（harness 自省）；② 模型知识；③ 可选增强：技能目录检索（如 SkillsMP）/ 网络搜索——有则用、无则降级，不阻塞。
- 纪律：对话版每条推荐注明来源与把握度（证据主义）；交付版不含来源/把握度（排练期元信息不进交付物）；宁缺毋滥，不为凑清单而推荐。

**M5 提示词装配**
- 输入：M3 种子核心 + M2 已确认结论清单 + M4 工具清单（+ 用户明确要求的内容）。
- 装配骨架（脚手架，槽位制——**有料才填，缺项整段省略**，不为凑齐而补）：

  ```
  【目标】
  【硬边界】
  【验收标准】
  【方向与偏好】      ← 已确认的方向性偏好：优先级、取舍倾向、质量取向（缺项省略）
  【背景与已确认结论】
  【环境与工具】        ← 交付版清单：名称/类型/为何选它/启用一句话
  【用户明确给出的流程】   ← 保留原文，不升格为约束
  ```

- 装配原则（引自 harness 工程实践，§14）：自足（全新上下文可独立执行）、高信号优先（关键信息置首尾）、最小充分集（不注水）。
- 槽位分工（我方裁定）：**事实与决策**进【背景与已确认结论】，**取向与偏好**进【方向与偏好】；后者只装用户明确确认的优先级/取舍倾向/质量取向，**绝不装步骤、方法、顺序**（防蓝图化）；两槽皆可回指 M2 已确认结论，有料才填，缺项整段省略。
- 内核纪律不变：每一段内容都可回指到上游模块产出或用户原话；骨架是外壳，内容自然成文。

**M6 提示词分析（意图解读）**（10-21 晚新增）
- 输入：任意表达——嘈杂口语、草稿、现成提示词（用户自写或他人写的均可）；输出：**意图理解**——想做什么、要什么、想表达什么；对象为现成提示词时输出「该提示词在要什么」；歧义与理解缺口随附列出（缺口供追问，不自行补全）。
- 纪律：理解是提炼不是发明（可回指到输入依据）；歧义先问不猜、不限次数；解读≠改写（不输出改写版）；不写实施方法。
- 双角色：独立调用时意图理解即交付物（对话内）；链路内插在 M1 与 M2 之间，产出「已理解意图 + 缺口清单」供 M2 追问，作中间产物**不进最终交付提示词**（裁定#5）。
- 派生组合（非新模块）：**提示词翻新**——M6 解读他人提示词 → 提取意图 →（用户确认后）走 M3/M5 生成链重做成种子。
- 与 M7 分工：分析管「它想做什么」，检查管「它写得合不合格」，互不越界。

**M7 提示词检查（/seed-check 升级）**（10-21 晚新增）
- 输入：任意提示词（用户自带或已装配；范围不收窄，继承 10-21 拍板）；输出（对话内报告）：**分项通过/不通过**（纲领项：三大病灶各目、软硬分家、目标与验收、可回指[若附原始意图]、自主空间）+ 问题清单（病灶/缺失/疑点）+ **合格判定** + **纪律符合度总结分**。
- 口径：合格 = 纲领病灶项全部通过；缺失/疑点分列标注、不判否（种子本就「说到多少写多少」；此合格线为我方推定，可改）。总结分只汇总纲领纪律符合度，报告必附「**只度量纲领纪律符合度，不预测实践效果**」声明。
- 评分红线：分数不得写成优化目标或交付门槛（裁定#7 边界）；不得因「详细/结构完整/有示例」加分——通用「好提示词」标准奖励的恰是三大病灶；分制内不放正例反例（裁定#3）。
- 形态：mod 主入口（cowork 可随包使用）；运行时探测到可派发子代理（Claude Code/桌面版）则派发 seed-reviewer 走独立上下文防自我美化，其体检口径同步升级为本口径；探测不到（cowork）则 mod 自身执行，独立性弱化属已知局限。
- 只诊断不改写不变；改写仍须用户另行发起、走生成族。

### 4.3 共享与自足

- **总纲入包**：`references/charter.md`（总纲 v4 原文）随每个 mod 自带副本（总纲冻结、我方不得改动 → 同步风险≈0，换来每个 mod 可独立分发/cowork 单装）；发布清单注明单一事实源核对。
- `anti-patterns.md`（T1–T13）为开发期资产，留在编排器侧，不随运行时读取。
- 每个 mod 的 SKILL.md 保留 v1 证明有效的解剖：运行步骤 / 内部纪律（执行但不输出）/ 禁止事项 / 资源。

## 5. 命令设计（a + c：递进链怎么拆、命令怎么定）

### 5.1 功能分层（a）

```
表达层（M1）→ 需求层（M2）→ 意图层（M3）→ 环境层（M4）→ 集成层（M5）
```

每层独立成命令；相邻层可手跑组合成子链（如"澄清完直接生成种子"）；全链路一键串通。

读取族（M6/M7）平行作用于任意现成提示词：M6 意图解读、M7 质检评分，不占生成链层位。

### 5.2 命令梯子（c）

| 命令 | 层 | 用途 |
|---|---|---|
| `/seed-express <文本>` | M1 | 只优化表达 |
| `/seed-clarify <主题或现状>` | M2 | 追问 / 头脑风暴 / 流程体检（按输入自动判断，可点名模式） |
| `/seed <文本>` | M3 | 只生成种子提示词 |
| `/seed-tools <需求>` | M4 | 只出工具推荐清单 |
| `/seed-assemble [材料]` | M5 | 装配成最终提示词（无参则取本次对话已有的各环节产出） |
| `/seed-analyze <表达或提示词>` | M6 | 只做意图解读（任意表达/现成提示词 → 意图理解） |
| `/seedify <原始文本>` | 全链路 | 一键一条龙：表达整理→意图解读→需求澄清→种子生成→工具挑选→装配 |
| `/seed-check <提示词>` | M7 | 提示词检查：分项通过 + 合格判定 + 纪律符合度总结分（升级 v1 体检；mod 主入口，可派发独立上下文） |

- **逐层递进**：想优化表达→`/seed-express`；想直接要种子→`/seed`；想全托管→`/seedify`。中间态靠命令组合（例如 clarify 后接 seed）。
- **自然语言触发**：v1 触发短语（含语音错字容错）全部保留并指向 `/seedify` 全链路；新增触发语义："预演/预热一下开工提示词""帮我看清方向"。
- **语义变更提示**：`/seed` 在 v1 是准全链路，v0.2 起收窄为纯种子生成；全链路迁至 `/seedify`。README 与 CLAUDE.md 同步注明；`/seed-check` 自 v0.2 起增加合格判定与总结分（10-21 晚裁定）。

## 6. 链路与两个时刻的走法

**全链路（时刻 A·开项目预演）**：
```
噪声输入 → [M1]干净表达 → [M6]意图理解与缺口 → [M2]追问/流程体检→已确认结论
        → [M3]种子核心 → [M4]工具清单 → [M5]装配
        → 交付：结构化提示词（代码块，仅此一件）
```

**中途迷路（时刻 B）**：
```
现状+乱思绪 → [M2]头脑风暴（候选方向，对话内挑选）
           → 可接 M1/M3 重造种子 → [M5]装配
           → 交付：把方向扳回来的提示词（代码块）
```

- 中间产物只活在对话里（干净表达 / 结论清单 / 种子核心 / 工具清单）；交付物永远只有一件。
- 用户补充/改口 → 从受影响的模块重走，不全链重跑。

**提示词翻新（读取族 → 生成族组合）**：
```
现成提示词 → [M6]意图理解 → （用户确认）→ [M3]种子核心 → [M5]装配
          → 交付：重做的种子提示词（代码块）
```

## 8. 与总纲 v4 的关系（关键澄清）

总纲 v4 **原文不动**。其"三、路线"写明 L1 种子只写目标+硬边界+验收、软细节留循环；其"四"把"第二步：种子提炼"留白（细则由设计文档承载）。本次用户裁定（§3）为该留白提供了新的内涵：

- **种子内核**（目标/硬边界/验收/用户明确内容）仍完全遵守总纲纪律；
- **装配层脚手架**（已确认结论、环境与工具、骨架槽位）是用户 2026-10-21 明确裁定的"合法增量"——它组织上下文、引导生长方向，但**不写实施方法、不替 Agent 做决定**，故与"种子不是蓝图"不冲突（脚手架不规定建筑怎么盖）；
- 是否把"脚手架"正式写入总纲（v5），**由用户日后亲定**；我方仅在本设计文档记录。

## 10. 开发期行为护栏（≠效果验收）

效果验收留白（§3）；以下是**行为护栏**，违反即 bug，开发期逐条实测：

- 继承 v1 T1–T13（按模块归属拆分映射，如 T1 禁增生→M3/M5，T2 零丢失→M1，T13 提问充分→M2）；
- 新增护栏（编号续 T14+）：装配缺项整段省略不补（T14）；工具清单对话版条条注明来源与把握度、交付版不得含来源/把握度（T15）；流程体检的建议只进对话不进交付物（T16）；头脑风暴候选不直接写入提示词、由用户挑选确认后才可进【背景与已确认结论】（T17）；单模块命令产出不得夹带其他模块的产物（T18）；`/seedify` 全链路交付仍是纯提示词（T19）；seed-reviewer 对含合法脚手架的装配产出不得误报越界、对脚手架越界（流程写成硬约束/未确认内容入段/元信息混入）仍逐项指出（T20）；【方向与偏好】槽内不得出现步骤/方法/顺序（T21）；意图解读每处可回指输入、歧义先问不臆断、解读不产出改写版（T22）；总结分只量纲领纪律符合度、报告附「不预测实践效果」声明、分数不作目标或门槛（T23）；评分不得因详细/结构完整/有示例加分（T24）；链内意图理解不进最终交付提示词（T25）；/seedify 不自动跑质检、交付仍纯提示词（T26）；分析产物不含质量评价、检查产物不含意图解读或改写（T27）。
