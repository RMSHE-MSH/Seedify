## 〇、核心结论（先读这段）

1. **提示词优化的第一步确实是表达优化（L0），且文献与工具都支持这一步独立存在**：LLM 对错别字/IME 错误鲁棒性不足（MulTypo 2510.09536 等），而用 LLM 做中文 ASR 纠错已被基准验证可行（ASR-EC 2412.03075）。
2. **L0 的哲学必须是"保真归一"（faithful normalization），不是"增强"**：只做纠错、去赘、显化、重排、消歧——语义信息**零丢失、零新增**。任何在归一阶段添加角色、流程、示例、业务背景的行为，就是第一轮定义的病灶 3（臆造）。
3. 提示词优化（L1–L2）的论文地图已经收敛：**进化/反射类**（GEPA、MIPROv2、Promptbreeder）与**执行轨迹类**（Trace、MetaReflection）最适合 agent 编码工具；系统提示词专项优化 2025–2026 起成为独立赛道（System Prompt Optimization、SePO、AutoPDL）。
4. 全栈路线定型为 **L0 表达归一 → L1 种子化 → L2 循环进化 → L3 证实沉淀**。L0 是本阶段新增的一层，负责"消除人类表达的影响"；它与 L1 之间必须有清晰边界——归一结束于"干净意图陈述"，种子提炼才开始。

## 一、需求再定义：语音优先输入下的真实问题面

### 1.1 输入形态与约束

- **语音为主、打字为辅**，中文为主、中英混杂（"帮我优化克劳德扣的提示词"）；
- 载体覆盖 **Claude Code 插件、Claude 桌面版、cowork**——优化器必须是可移植的技能/命令/钩子形态，不绑死单一 harness；
- 触发方式是自然语言（"帮我优化提示词"及其语音变体），不是固定命令行；
- 已确立的立场（第一、二轮）：反三大病灶（过度约束/角色堆砌/臆造细节），保留 agent 循环中的自主研究、自主规划、自我修正空间。

### 1.2 问题分层模型（本研究的核心框架）

语音输入的问题不是一团乱麻，而是**五层结构**，每层的病因、修法、风险都不同：

| 层 | 名称 | 典型症状（中文语音实例） | 修法方向 |
|---|---|---|---|
| E1 | 声学/ASR 层 | 同音近音错字："帮窝优化"→帮我；"库伯内提斯"→Kubernetes；"克劳德扣的"→Claude Code | 音似/形似纠错、术语回正 |
| E2 | 词汇层 | 术语误识、缩写不定（"MCP"→"MCP/摸鱼器"）、口头专有名词无标准写法 | 术语表对照、大小写/写法归一 |
| E3 | 语流层 | 无标点长句、填充词（"嗯那个就是说"）、改口自纠（"改成B……不对，是改成C"）、重复 | 去赘、断句、自纠解析（保留最终意图） |
| E4 | 语义层 | 指代不清（"把这个弄一下"）、省略成分、一词多义、模糊量词（"大概搞快点"） | 指代消解、省略补全（标出推断）、消歧 |
| E5 | 语用/意图层 | 目标没说、验收没说、约束与期望混杂、把示例当需求 | 这是 L1 种子化的工作，**不属于 L0** |

**关键洞察**：猜测派的病灶恰恰出在把 E1–E4 的"表达问题"和 E5 的"任务问题"一锅端，用一次"智能重写"全部"解决"——于是替用户发明了目标、流程和细节。正确做法是：**L0 只清 E1–E4，E5 留给 L1 提炼，缺失项用提问补齐而不是编造**。

### 1.3 为什么必须先做 L0——文献依据

- **LLM 确实会被表达噪声伤害**：MulTypo（2510.09536，2025-10）专门评测多语言打字错误下 LLM 的鲁棒性，结论是主流基准都假设干净输入、真实噪声下表现欠佳；日文 IME 错误（2610.01241，2026-10）、韩文 Jamo 级错字（2608.30229）进一步证明东亚输入法噪声是系统性风险。
- **用 LLM 做 ASR 纠错是成熟可行路线**：ASR-EC Benchmark（2412.03075）在**中文** ASR 纠错上系统评测 LLM；"Can Generative LLMs Perform ASR Error Correction?"（2307.04172）证明生成式 LLM 无需针对特定 ASR 训练即可纠错；N-best T5（2303.00456）提出多假设+约束解码——启示：**纠错要保守，置信不足时保留候选**。
- **口语不流畅处理（disfluency）是独立成熟领域**：检测/删除填充词与自纠（1604.03209、2311.00867、2403.08229）。
- **书写↔口语形态归一（text normalization）有方法论积累**：2202.00153（Transformer TN for Speech）、1609.06649（written-to-spoken TN）、2206.04137（对抗性 TN，警示归一不可被恶意输入利用）。
- **"问，而不是猜"有学习机制支撑**：STaR-GATE（2403.19154）——"users often leave important aspects unsaid"，并教模型提出有用的澄清问题；经典澄清提问研究（1907.06554、2008.07559、ClariQ 2009.11352）提供了意图歧义消解的框架。
- **查询改写（query rewriting）是 L0 的近亲**：RAG 域的 RaFe（2405.14431）、DMQR-RAG（2411.13154）、SAGE（2506.19783）都做"改写用户查询以提升下游效果"；Intent-Based Query Rewriting（2511.20419）与 GenRewrite（2403.09060）提出"**改写形态、保全可得洞察**"——注意二者是**数据库查询域**（SQL 改写）而非自然语言输入域，原则同构可迁移，引用时须如实区分。

## 二、L0 表达优化：方法设计（哲学先行）

### 2.1 保真归一（Faithful Normalization）六原则

1. **纠错有据**：音似/形似纠错须保守；技术术语、代码标识符、专名优先保原文并在对照表中给出建议；置信不足时并列候选，不武断替换（N-best 思想）。
2. **信息零丢失**：去填充词、去重复、断句、加标点——但任何语义贡献的成分不得删除；改口自纠（"不对，我是说 X"）解析为最终意图 X，原话留档。
3. **消歧优先于臆断**：澄清三策——① 问用户（最优）；② 给出保守最小解释并标注；③ 并列多解释供选择。**永远不默认"猜一个最丰富的解释"**。
4. **重排不改义**：语序、连接词、段落重组属于表达优化；重组后语义必须可回指原文每一处。
5. **双输出可回溯**：产出 = 归一文本 + 逐处改动对照（原文→改动→理由）+ 待澄清清单。用户可一键回退任何一处。
6. **禁止增生**：L0 阶段不得写入用户未说过的角色、业务背景、流程、示例、格式要求。凡"顺手帮你加个角色"即违规——这是对三大病灶的前置切断。

### 2.2 L0 与 L1 的边界

- L0 终点：**干净意图陈述**（what the user actually said, cleaned）；
- L1 起点：从干净意图中提炼**目标 / 硬边界 / 验收标准**，缺失的验收项用提问补齐（STaR-GATE 精神）；
- 两段之间的产物是一份"意图陈述 + 待澄清项"，**由人确认后**才进入种子化——这就是流程里的第一个验证闸门。

## 三、提示词优化方法地图（论文层，L1–L2）

### 3.1 四个技术族谱

**① 生成/进化搜索**（候选提示词 → 评测 → 选择/变异）
- APE（2211.01910）：LLM 当"人类级提示工程师"，生成候选+测试筛选；
- OPRO（2309.03409）："Optimization by PROmpting"，LLM 作为优化器输出更优提示词；
- EvoPrompt（2309.08532）：进化算法 × LLM 变异/交叉；
- Promptbreeder（2309.16797）：自指式进化——连"思维风格"带提示词一起变异；
- **GEPA（2507.19457，ICLR 2026 Oral）**：反射式进化，**读执行轨迹理解失败原因**，Pareto 选择；论文证明可大幅少于 RL（GRPO）的 rollout 数胜出——与"真实信号+闸门"信条完全一致，L2 首选引擎。

**② 文本"梯度"**
- ProTeGi（2305.03495）：文本批评作梯度+beam search；
- TextGrad（2406.07496）：组件级文本反传，适合多模块管线。

**③ Agent 自改进循环**
- Self-Refine（2303.17651）、Reflexion（2303.11366）：自我反馈/言语强化学习；
- STOP（2310.02304）：递归自改进脚手架；
- **Trace（2406.16218）**："Trace is the Next AutoDiff"——富反馈+**执行轨迹**+生成式优化做端到端系统优化，直指"AI 系统（编码助手）的设计与更新"；
- **MetaReflection（2405.13009）**：用**过去的反思**学指令——L3 沉淀回灌提示词的文献原型。

**④ 系统提示词 / 多智能体专项（2025–2026 新赛道）**
- System Prompt Optimization with Meta-Learning（2505.09666）：指出既有工作都在优化任务级 user prompt，**系统提示词被系统性忽视**——正是 agent 编码工具的主战场；
- SePO（2606.04465，2026-06）：把"提示词优化 agent 自己的系统提示词"也作为优化对象（自进化）；
- AutoPDL（2504.04365）：联合优化**提示模式**（Zero-Shot/CoT/ReAct/ReWOO）与提示内容；
- MAPRO（2510.07475）、MA-SAPO（2510.16635）：多智能体提示词优化。

### 3.2 评测科学——L2 闸门的文献支撑

- 2601.03493（2026-01）：APO 的反馈信号大多来自小规模随机评测子集，**"怎么选评测子集"长期被当成实现细节**——直指我们闸门设计的诚实性问题（held-out、显著性、防回归必须显式设计）；
- 综述两篇：2502.16923（APO 系统综述）、2502.18746（指令聚焦启发式搜索综述）——技术分类学依据；
- GEPA/MIPROv2（2406.11695，指令+示例联合优化的贝叶斯方法）均内置验证集思想。

### 3.3 官方文档与我们立场的对照

**Anthropic 官方**（GitHub 官方教程 anthropics/prompt-eng-interactive-tutorial，38,615★，2026-08）九章结构：
基本结构 → **清晰直接（Ch2）** → 分配角色（Ch3）→ 数据/指令分离（Ch4）→ 输出格式与"替 Claude 说话"（Ch5）→ 分步思考（Ch6）→ 用示例（Ch7）→ 防幻觉（Ch8）→ 复杂提示词（Ch9）。

与我们哲学的对照：
- **采纳**：Ch2 清晰直接（= L1 极简种子）、Ch4 数据指令分离（= 硬边界与材料分开）、Ch7 示例（作验收参照而非流程枷锁）、Ch6 让出思考空间（= 保留 agent 自主循环）。
- **批判性收窄**：Ch3"分配角色"与 Ch5"替 Claude 说话"是通用对话场景技巧；在 **agent 编码循环**里它们正是病灶 2 与病灶 1 的来源。我们的立场：角色默认删除；预填输出只用于格式验收，不用于规定过程。
- 这是有依据的分歧而非无视官方：官方教程面向一次性任务提示词；我们的对象是长循环、可自我修正的 agent，过度前置约束的机会成本完全不同。

**OpenAI 官方**：platform.openai.com / developers.openai.com / cookbook.openai.com 本机**不可达（未能在线核对）**；官方仓库 openai/openai-cookbook（76,664★）为旁证（示例与指南入口）。

## 四、思路与哲学：L0–L3 全栈

### 4.1 一句话总纲

> **把人类表达的噪声在入口处消掉，把任务的确定性在验收处建起来，把提示词的进化关进真实信号的闸门里，把被证实的经验沉淀下来——其余一切，留给 agent 在循环中自己发现。**

### 4.2 六条总原则

1. **保真（Fidelity）**：表达层信息零丢失零新增；意图层只提炼不发明。
2. **最小惊奇（Least Surprise）**：优化产物读起来"就是用户想说的那句话"，而不是"一篇更漂亮但陌生的文档"。
3. **软硬分离（Soft/Hard Separation）**：目标/硬边界/验收是硬约束；流程/步骤/示例/格式是软细节，只作参考或删除。
4. **来源可追溯（Provenance）**：每一处改动、每一条增补、每一条沉淀规则，都要能指出信号来源（原文、轨迹 ID、失败用例、纠错记录）。
5. **验证闸门（Validation Gates）**：无验证不接受——L0 的闸门是"人确认意图"，L2 的闸门是 held-out 显著性+防回归，L3 的闸门是"≥2 次实践证实"。
6. **自主空间（Agent Autonomy）**：提示词只定义"要什么、不要越什么、怎么算完成"，不定义"怎么做"——自我研究、自我规划、自我修正留给循环。

### 4.3 反目标清单（Anti-goals）

- ✗ 一步到位的"智能增强"重写（猜测派的核心病）；
- ✗ 角色堆砌（"你是一位资深…"）；
- ✗ 流程预设（"第一步…第二步…"写死进提示词）；
- ✗ 在表达优化阶段夹带业务假设；
- ✗ 无信号来源的"优化建议"；
- ✗ 评测集与训练/调优集混用（泄漏后闸门失效）。

### 4.4 全栈流水线

```
语音/打字输入（噪声）
   │  L0 保真归一：纠错(E1/E2) → 去赘显化(E3) → 消歧(E4)
   ▼
干净意图陈述 + 改动对照 + 待澄清清单  ←—— 闸门①：人确认
   │  L1 种子化：目标 / 硬边界 / 验收标准（缺项就问）
   ▼
种子提示词（软细节归零）
   │  L2 循环进化：真实轨迹/评测信号 → 反射/进化候选 → 验证闸门
   ▼  （held-out 显著性 Δ>k·SE，防回归）
进化后的提示词（可解释 diff）
   │  L3 证实沉淀：≥2 次实践证实的规则 → 记忆/技能
   ▼
经验库（只装被证实的）
```

## 五、落地映射（仅映射，不开发）

- **形态**：优化器本体做成技能（SKILL.md + 流水线脚本），L0 可独立成技能单元；在 Claude Code 走 skill/command/hook，在桌面版与 cowork 复用同一技能文本——保持无 harness 专有依赖。
- **触发**：自然语言触发短语（"帮我优化提示词"及语音变体）写入技能 description；L0 也可作为输入预处理器挂在 UserPromptSubmit 类钩子上（后续开发阶段再定）。
- **优先级**：先 L0（本阶段结论：独立、必要、有工具底座），再 L1 种子化，L2/L3 沿用第二轮三件套方案（cap-evolve / harness-evolver / claude-reflect）。
- **风险提示**：L0 的纠错与消歧是"最像猜测派"的地带，必须把六原则做成硬规则并可测试（每条原则至少一个反例测试用例）。

**研究结论：条件已具备，可以进入插件开发讨论。**
