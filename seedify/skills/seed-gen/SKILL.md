# seed-gen（种子生成）

从干净意图自主成文种子提示词——种子是种子不是蓝图，自然生成、形式自由。只交付种子本身：独立调用时交付代码块，链路内产出种子核心供装配环节使用。

## 运行步骤

1. **先读思想纲领**：读取 `references/charter.md`，领会核心思想后再动手。任何产出不得违背该纲领。
2. **取意图**：取调用参数或触发上下文中的干净意图；上下文中确无意图时，才用一行话索要。不自行代行上游的表达整理或需求澄清——上游已产出什么就以什么为底。上游可提供提示词构建方案：按方案的构建路线与取舍成文；方案不写逐句文本，种子仍自然生成。
3. **有疑必问（先问后写）**：意图含糊、要素缺失、存疑或需确认处，先向用户提问，问清后再成文。提问一律开放问法，禁填空模板；提问次数不设上限，不受输出克制要求的限制。链路内缺项或存疑时，本模块到此为止，把缺口交回编排器调度澄清环节追问；单模块调用时，直接向用户开放提问。用户明确表示没有的要素不写；用户不愿再澄清的，零添补成文——只写意图里有的，不引入意图之外的内容。
4. **种子自主成文**（过程不输出，只出成文结果）：
   - 形式自由——一段、数行或一句均可，不套格式；
   - 目标、硬边界、验收标准三者仅作提示：意图中说到哪些写哪些、说到多少写多少，不为凑齐而补；
   - 实施方法（流程、步骤、角色、示例、格式）默认不写；用户明确要求写入实施方法时，按其要求写入；
   - 用户明确表示没有的要素，不写；任何要素缺失或存疑，回到第 3 步先问。
5. **成文后自检**（纯内部执行，不输出）：可回指吗——种子每处内容都能对应意图依据？写了实施方法吗——有无流程/步骤/角色/示例/格式混入？为凑内容添了东西吗——有无为补齐要素而臆造？任一不过即处理：删除即愈则删、存疑才问（回到第 3 步）。
6. **输出**：独立调用时只交付种子提示词，置于代码块中便于复制；链路内只产出种子核心，供装配环节使用。不输出过程痕迹（改动对照、改动依据、整理过程、总结）。不自动开工。用户补充信息或要求修改时，回到第 4 步重走。

## 内部纪律（执行但不输出）

- **可回指**：种子的每一处内容都能在意图（或用户对提问的答复）中找到依据；找不到依据的内容属于臆造，不得写入。
- **信息零丢失**：意图的语义成分不得在成文中消失——用户说到的具体细节（数字、时间、对象、限定条件）写入种子，不静默丢弃。
- **自然生成**：种子由意图自然成文，不套固定格式、不套栏位、不代拟用户没说的内容。
- **三大病灶自检**：成文中不得出现——把软细节（流程、步骤、示例、格式）当硬约束写死；角色堆砌与铺垫（"你是一位资深……"）；臆造的要求与细节。
- **三要素仅作提示**：目标、硬边界、验收标准是成文时的提示性考虑，不是必须填满的清单；缺与不缺以意图实说了什么为准，不以清单核对为准。
- **缺项必问不编造**：该有的信息意图里没有 → 先问，问清再写；用户说没有 → 不写；绝不代填、绝不编造。

## 禁止事项

- 只做种子生成：不做表达整理（归 seed-express）、不做意图解读（归 seed-analyze）、不做质量体检（归 seed-check）、不展开需求追问本身（归 seed-clarify，本模块只就成文所需缺口提问并交回）。
- 正例、反例不得写入本技能的任何文件，也不得作为说明性内容输出。
- 不设提问次数、篇幅、Token 等硬性指标（对自身产物的硬指标即元层面过约束）。
- 不调用外部服务、不执行脚本。
