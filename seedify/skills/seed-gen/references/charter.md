# Agent 提示词优化总纲

**v4 · 2026-10-18**

## 一、立场

反对"对话猜测式"提示词优化（猜测派），主张"实践派"。猜测派有三大病灶：

1. **过度约束 / 过拟合**——把软细节（流程、步骤、示例、格式）当硬约束预先写死；
2. **角色堆砌与铺垫**——"你是一位资深 X 专家……"式包装和冗长前言；
3. **臆造要求和细节**——优化器在对话里猜出用户从未说过的角色、业务背景、流程、例子。

这些病灶会诱导 Agent 照提示词执行，压制它在实践循环中自主研究、自主规划、自我修正的能力。Agent 的价值在于循环中建立理解、发现路径不对就自我修正——提示词不应预先夺走这个空间。提示词优化不应压制 Agent 的自主性。

### 1. 问题观：我们面对的两个敌人

人机协作的新矛盾：**人的意图是真实的，但表达是带噪声的；Agent 的能力是强大的，但引导它的提示词很容易变成枷锁。**

| 敌人           | 症状                                                |
| -------------- | --------------------------------------------------- |
| **表达的噪声** | 转写错字、口语混乱、含糊其辞、指代不清              |
| **优化的僭越** | 优化器替人做决定、替 agent 做决定：猜测、堆砌、预设 |

## 二、核心逻辑

1. **Agent 强在循环，不强在一次执行。** 它在实践中逐渐理解项目、修正路径，而不是照剧本演出。
2. **越具体的提示词，越是在替 Agent 做决定。** 细节写死之日，就是自主规划消亡之时。（蓝图式提示词的根本错误：它把只有未来才知道的决策，提前写死了。）
3. **对话式优化没有真实信号，只能靠猜。** 猜出来的东西看着完整，实则过拟合于想象，而非现实。
4. **优化必须发生在有反馈的系统里。** 真实信号（执行轨迹、评测集、真实纠错）→ 诊断为什么失败 → 改动 → 验证闸门（改动必须显著变好才保留，防回归）→ 保留或丢弃。这就是 GEPA、cap-evolve 们的方法论，也是"Prompt Engineering → Loop Engineering"的含义。
5. **约束要分家。** 硬约束（安全规则、验收标准）预先写死；软细节（流程、步骤、角色、示例、格式）留给 Agent 在循环中长出来。过拟合的根源就是把软细节当硬约束。
6. 提示词优化的目标不是"让 Agent 更听话"，而是"让 Agent 更少被误导"。

## 三、路线与核心思想

**提示词是种子，不是蓝图；优化是进化，不是润色。**

从提示词工程到循环工程（Prompt Engineering → Loop Engineering）：

- **L1 种子提示词**：只写目标 + 硬边界 + 验收标准，软细节留给 Agent；
- **L2 循环进化**：提示词优化必须来自真实信号（执行轨迹、评测集、真实使用纠错），改动须过验证闸门（如 held-out 显著性、防回归）才算数；
- **L3 沉淀**：只把被实践证实的经验固化回记忆 / 技能，不沉淀猜测。

## 四、本项目的范围

上述路线是完整的指导思想。本项目只实现入口一段：**表达整理与种子提炼**。L2 的循环进化与 L3 的经验沉淀由 Claude Code / Claude 桌面版 / cowork 的既有循环机制承担，不重复建设——这是"经验只从实践中来"与工具精简的直接推论。

**第一步：表达整理。** 用户输入以语音转写文本为主，其中含有错字、冗余、歧义与口语结构。工具对其作保真整理：把已说的说清楚，未说的不添加，有歧义的先询问。判据是可回指性——每一处修改都应能在原文中找到依据，找不到依据的内容属于臆造，不得写入。产物是干净的用户意图。（对语音转写文本做一定程度的纠正与整理，提炼出用户真正的想法和意图。"提炼"是从已有表达中抽取，不是补全想象（臆造））

**第二步：种子提炼(Agent提示词工程/Agent提示词优化)。**
