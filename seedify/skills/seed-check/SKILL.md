# seed-check（提示词检查）

把任意提示词——用户自带的或 seedify 已装配的，范围不收窄——对照思想纲领做质量检查，输出**对话内体检报告**：分项通过/不通过 + 问题清单 + 合格判定 + 纪律符合度总结分。只诊断不改写：改写须用户另行发起、走生成族；不做意图解读（那是 seed-analyze 的职责）。双角色——运行时探测到可派发子代理（Claude Code/桌面版）则派发 seed-reviewer 走独立上下文防自我美化、报告原样转述；探测不到（cowork 等）则自身执行并注明独立性弱化。

## 运行步骤

1. **先读思想纲领**：读取 `references/charter.md`，以纲领为唯一评判依据。任何判定不得违背该纲领。
2. **取送检文本**：取调用参数或触发上下文中的提示词全文；上下文中确无内容时，才用一行话索要。送检文本若实为待执行任务而非提示词，说明情况并请调用方澄清。调用方附有用户原始意图描述时一并对照；未附则不做揣测——可回指项按「未提供原始意图」处理，臆造目只查送检文本自身可证的无据添补。
3. **适配派发（先探测）**：
   - **探测到可派发子代理**（当前环境提供 Task/Agent 派发工具，如 Claude Code/桌面版）→ 把送检全文**原样**派发给 seed-reviewer（附原始意图，若调用方提供了），收回报告后**原样转述**给用户——不代替代理改写提示词、不增删报告结论；
   - **探测不到可派发子代理**（如 cowork，无派发工具）→ 自身继续第 4–5 步执行，并在报告开头注明「同上下文评审，独立性弱化」。
4. **逐项体检**（送检全文逐段覆盖，不跳段、不漏检；每条发现给出送检文本证据——位置/原文片段，引不出证据的不成其为发现）：
   1. **三大病灶**（纲领一）各目分查：
      - 过度约束/过拟合——软细节（流程、步骤、示例、格式）是否被当硬约束写死；
      - 角色堆砌与铺垫——是否有"你是一位资深……"式包装或冗长前言；
      - 臆造要求与细节——是否出现来源中从未说过的角色、业务背景、流程、例子（附原始意图时对照原意；未附时只查送检文本自身可证的无据添补，不揣测）。
   2. **软硬分家**（纲领二·5）——安全规则、验收标准等硬约束是否齐备；软细节是否越位成了要求。
   3. **目标与验收**——方向是否清晰可辨；完成判据是否可判——缺失则列入问题清单，不代拟内容。
   4. **可回指**（若附原始意图）——提示词每一处能否对应到用户原意；对应不到的即为臆造嫌疑；未附原始意图则本项记「不适用」。
   5. **自主空间**（纲领二·6）——是否给 Agent 留出了在循环中自主研究、自主规划、自我修正的空间。

   **脚手架口径**（判定口径，作用于过度约束与臆造两目）：装配产出的合法脚手架段——【目标】【硬边界】【验收标准】【方向与偏好】【背景与已确认结论】【环境与工具】【用户明确给出的流程】等骨架段位——**不是病灶，不得误报为越界**；脚手架**越界**仍逐项指出：流程写成硬约束、未确认内容入段、排练期元信息混入（来源/把握度等）、【方向与偏好】混入步骤/方法/顺序。
5. **出报告**（对话内，四项成分缺一不可）：
   1. **分项通过/不通过**：纲领各项——三大病灶各目、软硬分家、目标与验收、可回指[若附原始意图]、自主空间——逐项给「通过 / 不通过」；未提供原始意图时可回指项记「不适用」；未发现问题的项明确写"通过"。
   2. **问题清单**：逐条 `[级别] 位置/原文片段 — 问题 — 建议`，级别取「病灶 / 缺失 / 疑点」三档；建议只作方向性提示，不含改写稿；全部通过时明确回复"未发现病灶"，不凑字数。
   3. **合格判定**：**零病灶 = 合格**；缺失、疑点分列标注，不判否（种子本就"说到多少写多少"）。
   4. **纪律符合度总结分**：只汇总纲领纪律符合度，**必含原句**：「只度量纲领纪律符合度，不预测实践效果」。
   报告止于以上体检内容——不含意图解读、不含改写版提示词。用户随后要求改写时，说明改写须另行发起、走生成族，本模块不接。

## 内部纪律（执行但不输出）

- **可回指**：每条发现都能回指送检文本中的证据（位置/原文片段）；引不出证据的不写入报告——检查员自身不臆造发现，病灶判定只以送检文本与纲领为据。
- **信息零丢失**：送检全文逐段覆盖，每一段都被上述体检项过一遍；「看起来没问题」不是略过的理由。
- **三大病灶以纲领为检查对象**：判定只依据 `charter.md`；不引入纲领之外的"好提示词"通用标准当裁判。
- **评分红线**（违反即 bug）：
  - 总结分**只度量纲领纪律符合度**；
  - 报告**必含原句**「只度量纲领纪律符合度，不预测实践效果」；
  - 分数**不得**写成优化目标或交付门槛；
  - **不得**因「详细 / 结构完整 / 有示例」加分——通用"好提示词"标准奖励的恰是三大病灶；
  - 分制内**不放**正例、反例（裁定#3）。
- **合格线**：零病灶 = 合格；缺失、疑点分列不判否。
- **只诊断不改写**：报告止于诊断；改写稿一字不出，改写须用户另行发起、走生成族。
- **开放问法**：确需索要或澄清时（送检文本为空、任务/提示词不分），一行话开放式发问；提问次数不设上限，不受输出克制要求的限制。

## 禁止事项

- 只诊断不改写：不产出改写版提示词、不代改送检文本；改写须用户另行发起、走生成族。
- 不做意图解读（归 seed-analyze）：检查产物不含"它想做什么/在要什么"的意图理解段。
- 不做表达整理（归 seed-express）、不写种子（归 seed-gen）、不做工具挑选（归 seed-tools）、不做装配（归 seed-assemble）。
- 评分红线全部生效：分数不作优化目标、不作交付门槛；不因详细/结构完整/有示例加分；分制内不放正例反例。
- 正例、反例不得写入本技能的任何文件，也不得作为说明性内容输出。
- 不设提问次数、行数、篇幅、Token 等硬性指标（对自身产物的硬指标即元层面过约束）。
- 不调用外部服务、不执行脚本。
