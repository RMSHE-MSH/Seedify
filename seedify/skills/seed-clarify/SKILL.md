# seed-clarify（需求澄清）

M2 薄入口：先追问后方案——串追问席（grilling）与方案席（to-spec），把含糊需求在对话内谈透并综合成构建方案。产物=两席产物（追问共识 → 构建方案）；不产出交付用提示词。

## 运行步骤

1. **先读思想纲领**：读取 `references/charter.md`，领会核心思想后再动手。任何产出不得违背该纲领。
2. **取输入**：取调用参数或触发上下文中的表达/现状描述；上下文中确无输入时，才用一行话索要。
3. **追问**：调用技能 `grilling` 承载追问，把需求谈透成共识；有文档沉淀（术语对齐、语境词典）需要时叠加 `domain-modeling`。运行时探测不到 Skill 派发能力时，改读 grilling（及 domain-modeling）的 SKILL.md 按其执行，不报错、不阻塞、不作为硬依赖。流程体检请求=就用户流程开一轮 grilling（压力测试与建议都在问答内；用户流程可回指、评估不升格为约束，T16 随行）。
4. **方案**：追问共识谈定后，调用技能 `to-spec` 把共识综合成提示词构建方案；探测不到派发同样改读其 SKILL.md 按其执行。
5. **交批准门**：方案在对话内呈现给用户审阅，批准前不写提示词；用户改口时，从受影响的环节重走。

## 内部纪律（执行但不输出）

- **可回指**：共识与方案的每一条都能回指到用户确认过的话；找不到依据的内容属于臆造，不得写入。
- **信息零丢失**：用户确认过的内容不得静默丢弃——事实、决策、取向偏好、用户流程细节都收录。
- **过程痕迹不输出**：改动对照、依据、整理过程、总结均为内部检查项，不作为交付内容呈现。

## 禁止事项

- 不代行 M3/M5：不做种子成文（归 seed-gen）、不做装配（归 seed-assemble）；不做表达整理、工具推荐、意图解读、质检（各归其模块）。
- 不落盘：共识与方案都活在对话内，不写任何文件。
- 方案不进最终交付代码块——那是提示词的位置。
- 正例、反例不得写入本技能的任何文件，也不得作为说明性内容输出。
- 不设提问次数、篇幅、Token 等硬性指标；提问本身不受输出克制要求的限制。
