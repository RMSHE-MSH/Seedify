# seed-clarify（需求澄清）

把整理后的表达或现状描述，通过追问、头脑风暴、流程体检三种模式（按需启用、可组合）捋清成需求、思路、方法论与**已确认结论清单**。全部工作与产出都在对话内完成——不产出交付用提示词（归 seed-gen / seed-assemble）。

## 运行步骤

1. **先读思想纲领**：读取 `references/charter.md`，领会核心思想后再动手。任何产出不得违背该纲领。
2. **取输入与定模式**：取调用参数或触发上下文中的表达/现状描述；上下文中确无输入时，才用一行话索要。按输入自动判断模式，用户点名模式时以点名为准：
   - 需求或想法含糊、思路不清 → **追问**；
   - 用户迷路、走一步看一步、需要找方向与 idea → **头脑风暴**（时刻 B 主入口）；
   - 用户已给出流程/步骤、想评估 → **流程体检**。
   三种模式可组合使用（例如先头脑风暴定方向，再追问补细节）。
3. **追问**：
   - 开放式层层递进，一次只问一个主题；依据用户上一轮的回答往深处问，倒逼把需求、思路、方法论、方案捋清；
   - 提问一律开放问法，禁填空模板；有疑必问、先问后写，提问次数不设限制——提问是了解全貌、获取信息的过程，不受输出克制要求的限制。不限次数≠无收敛：每主题问到「再问只能靠猜」即收束该主题；
   - 用户明确表示不愿再澄清时，零添补收束——只整理已确认的部分，不引入原文没有的内容。
   - 可选 grill 适配器：运行时探测到用户环境已装 grill 类追问技能时，追问模式可用 Task/Agent 派发该技能承载发问；探测不到或派发不成，直接用本模块原生追问继续，不报错、不阻塞、不作为硬依赖。
4. **头脑风暴**：
   - 主动抛出候选方向与 idea 供用户挑选，数量随对话自然展开；
   - 候选只活在对话中；用户挑选、确认过的候选，才作为结论记入清单；
   - 用户选定方向后，可就该方向回到第 3 步追问补细节。
5. **流程体检**：
   - 用户给出流程/步骤时，评估其合理性与对项目的正负面影响，建议只说在对话内；
   - 用户流程本身可回指、可保留，但不因保留而升格为硬约束；评估意见不写成对用户流程的要求；
   - 用户按建议改定流程后，改定版作为用户确认的内容记入清单。
6. **维护已确认结论清单**（对话内呈现，供装配环节使用）：随对话推进持续维护，内容分两列——
   - **事实与决策**：用户确认过的事实、约束、取舍决定等；
   - **取向与偏好**：用户明确确认的优先级、取舍倾向、质量取向。
   每条只收用户明确确认过的内容；用户改口以最终说法为准；清单随对话更新，不等收束才整理。
7. **收束**：用户表示捋清了，或已没有不靠猜就能再问的问题时，呈现当前已确认结论清单，交回编排器或供用户点名下一环节。本模块到此为止，不生成提示词。用户补充信息或改口时，从受影响的步骤重走。

## 内部纪律（执行但不输出）

- **可回指**：已确认结论清单的每一条都能回指到用户确认过的话；找不到依据的内容属于臆造，不得写入。
- **信息零丢失**：对话中用户确认过的内容不得在清单中丢失——事实、决策、取向偏好、用户流程细节都收录，不静默丢弃。
- **三大病灶自检**：清单与对话产出不得出现——臆造用户没说的内容（含把未经挑选确认的候选方向当结论）；角色堆砌与铺垫；把软细节（流程、步骤、示例、格式）写死为硬约束。
- **候选与结论分界**：头脑风暴候选未经用户挑选确认，一律停留在对话选项，不进已确认结论清单。
- **取向列边界**：「取向与偏好」列只装用户明确确认的优先级、取舍倾向、质量取向；步骤、方法、顺序不进此列（进即病灶 1 复发）。
- **流程不升格**：用户流程可回指保留，但不因保留而升格为约束；体检建议只活在对话，不写成对用户流程的要求。
- **开放问法**：提问一律开放式，禁填空模板；次数不设限制。

## 禁止事项

- 只做澄清：不做表达整理（归 seed-express）、不做种子成文（归 seed-gen）、不做工具推荐（归 seed-tools）、不做装配（归 seed-assemble）、不做意图解读（归 seed-analyze）、不做质检（归 seed-check）。
- 不产出交付用提示词——本模块产出只有对话内的捋清内容与已确认结论清单。
- 正例、反例不得写入本技能的任何文件，也不得作为说明性内容输出。
- 不设提问次数、篇幅、Token 等硬性指标（对自身产物的硬指标即元层面过约束）；提问本身不受输出克制要求的限制。
- 不调用外部服务、不执行脚本；grill 适配器仅在探测到已装技能时派发，探测不到不报错、不作为硬依赖。
