# seed-assemble（提示词装配）

把上游各环节产出——种子核心、已确认结论清单（事实与决策 / 取向与偏好两列）、交付版工具清单、用户明确要求的内容——按装配骨架拼装成一份完整结构化提示词（种子内核 + harness 脚手架段），置于代码块中交付。产出只有这一件：一段可原样粘进新会话/项目使用的提示词。

## 运行步骤

1. **先读思想纲领**：读取 `references/charter.md`，领会核心思想后再动手。任何产出不得违背该纲领。
2. **取材料**：取调用参数或触发上下文中的上游产出——种子核心、已确认结论清单、交付版工具清单、用户明确要求的内容；上下文中确无材料时，才用一行话索要。上游已产出什么就以什么为底：不代行表达整理（归 seed-express）、不代行需求澄清（归 seed-clarify）、不代写种子（归 seed-gen）、不代挑工具（归 seed-tools）。逐项清点：某类材料上游未产出，即该类"无料"，记入第 4 步的省略判断；材料之间相互矛盾、语义不明、无法确定归属槽位时，先向用户提问问清再装配——开放问法、次数不设上限，不代为解读、不自行择一。
3. **按装配骨架拼装**（骨架原文照抄设计 §4.2，槽位制——骨架是外壳，槽内内容自然成文，不套栏位式填表）：

   ```
   【目标】
   【硬边界】
   【验收标准】
   【方向与偏好】      ← 已确认的方向性偏好：优先级、取舍倾向、质量取向（缺项省略）
   【背景与已确认结论】
   【环境与工具】        ← 交付版清单：名称/类型/为何选它/启用一句话
   【用户明确给出的流程】   ← 保留原文，不升格为约束
   ```

   槽位分工（钉死，按来源安置）：
   - **【目标】【硬边界】【验收标准】** ← 种子核心（M3）中对应的语义成分，按种子自然成文的形态落入；种子核心未涉及的成分，对应槽位无料。
   - **【方向与偏好】** ← 已确认结论清单的**取向与偏好**列：只装用户明确确认的优先级、取舍倾向、质量取向；**绝不装步骤、方法、顺序**。
   - **【背景与已确认结论】** ← 已确认结论清单的**事实与决策**列：用户确认过的事实、约束、取舍决定。
   - **【环境与工具】** ← M4 交付版工具清单，逐条按名称/类型/为何选它/启用一句话入槽；来源、把握度属排练期元信息，一个字不进。
   - **【用户明确给出的流程】** ← 用户给的流程**原文**保留，不改写、不升格为约束。
   - 用户明确要求的其他内容，按其语义归入相应槽位。
4. **有料才填，缺项整段省略**：某槽位无料（上游未产出对应内容）时，该槽位**整段省略**——不写占位、不补写、不为凑齐七段而注水；用户明确表示没有的，同样不写。
5. **装配原则自检**（纯内部执行，不输出）：
   - **自足**——全新上下文可独立执行：提示词不依赖本对话的上下文残留；
   - **高信号优先**——关键信息（目标、硬边界）置于首尾；
   - **最小充分集**——不注水，删去一切非必要的重复与铺陈；
   - **可回指**——每一段内容都能对应上游产出或用户原话；
   - **三病灶复核**——有无为凑槽位增生内容（角色/流程/示例/风格混入、无料补写）？有无把软细节写死（用户流程被升格为约束、方向与偏好混入步骤/方法/顺序）？有无臆造（未经确认的候选、上游没产出的内容入段）？任一不过，回到第 2、3 步重走。
6. **输出**：只交付完整结构化提示词，置于代码块中便于复制。不输出改动对照、改动依据、整理过程、总结，不输出来源、把握度等排练期元信息。不自动开工。用户补充材料或改口时，从受影响的步骤重走。

## 内部纪律（执行但不输出）

- **可回指**：装配后每一段、每一处内容都能在上游产出（种子核心、结论清单两列、交付版清单）或用户原话中找到依据；找不到依据的内容属于臆造，不得入段。
- **信息零丢失**：上游语义成分不得在装配中消失——种子核心说到的目标、硬边界、验收成分，结论清单两列的每一条，交付版清单每条的四个字段，用户明确要求的内容与用户流程细节，装配后全部仍在；遗漏即回查，而不是当它不存在。
- **三大病灶自检**（按 M5 职责）：不增生——不为凑齐槽位补写上游没有的内容、不代拟角色/流程/示例/风格；不把软细节写死——用户流程保留原文不升格为约束，【方向与偏好】绝不装步骤/方法/顺序，脚手架只组织上下文、不替 Agent 预设怎么干；不臆造——未经用户挑选确认的内容、上游未产出的槽位内容，一律不入段。
- **槽位分工边界**：事实与决策只进【背景与已确认结论】，取向与偏好只进【方向与偏好】，两列不混装；步骤、方法、顺序两槽皆不收。
- **缺项省略不补**：无料槽位整段省略，省略是正确处理，补写是 bug。
- **排练期元信息不进交付物**：改动对照/依据/整理过程/总结/来源/把握度一律留在对话，交付物物理上不含这些内容。
- **骨架是外壳**：槽位组织结构，内容自然成文；不把骨架写成栏位式填表说明。

## 禁止事项

- 只做装配：不做表达整理（归 seed-express）、不做需求澄清（归 seed-clarify）、不写种子本身（归 seed-gen）、不做工具推荐（归 seed-tools）、不做意图解读（归 seed-analyze）、不做质检（归 seed-check）。
- 产出只有完整结构化提示词这一件；改动对照、改动依据、整理过程、总结、来源、把握度等排练期元信息一律不进交付物。
- 缺料槽位不许补写：不写占位、不代填、不为凑齐七段注水；臆造内容一律不入段。
- 正例、反例不得写入本技能的任何文件，也不得作为说明性内容输出。
- 不设行数、篇幅、Token 等硬性指标（元层面过约束即病灶复发）。
- 不执行脚本、不调用外部服务；交付后不自动开工。
