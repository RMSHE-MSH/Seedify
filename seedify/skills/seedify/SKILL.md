# seedify（种子化 · 编排器）

把带转写噪声的口语输入，经七模块与两席串链整理、澄清、生成、装配，只交付提示词本身。本编排器是薄层：只做触发入口、边界判断、按需串链、交付即止——各模块的规则全部住在各模块自己的 SKILL.md 里，本文件不复述。

## 运行步骤

1. **先读思想纲领**：读取 `references/charter.md`，领会核心思想后再动手。任何产出不得违背该纲领。
2. **取输入**：取触发短语前后的完整上下文作为原始输入（斜杠调用时即参数）；上下文中确无待处理文本时，才用一行话索要原文。
3. **边界判断**（沿 v1）：
   - 输入本身是一个待执行任务而非待优化的提示词草稿，先问清一句："这是要直接执行，还是先整理成提示词？"答复为直接执行时，退出本技能、按正常对话处理该任务；答复为整理成提示词时，继续第 4 步；仍难判断时继续追问。
   - 用户点名单个模块（如只要表达整理、只要意图解读、只要工具清单、只要提示词检查）时，交由对应模块单独执行、到其交付为止，不自动续链——单模块调用的产物只含该模块产物，不夹带其他模块的产物。
4. **按需串链**（模块即同级目录；每个环节的契约读对应模块的 SKILL.md，本文件不复述）：
   - **典型全链（含噪输入）**：`seed-express` 干净表达 → `seed-analyze` 意图理解与缺口清单 → `grilling` 追问至共识（可叠 `domain-modeling`）→ `to-spec` 构建方案 → **批准门** → `seed-gen` 种子核心 → `seed-tools` 工具清单（对话版+交付版）→ `seed-assemble` 装配成结构化提示词。
   - **门规则**：走方案席的链路，构建方案须经用户批准才进生成/装配——方案批准前不写提示词；跳层与单模块直调不受此门约束。
   - **跳层**：输入已是干净表达 → 从 `seed-analyze` 起；意图已清晰 → 从 `seed-gen` 起；已有种子核心 → 直接 `seed-assemble`；跳层与单模块直调不受批准门约束。缺料或存疑 → 按该模块契约交回，由编排器调度 `grilling` 追问，问清后从受影响的环节续链——不跳问、不代答。
   - **中途迷路（现状+乱思绪）**：从 `grilling` 追问起步，用户挑定方向后按需经 `seed-express`（输入仍含噪时）/ `seed-gen` 重造种子，再到 `seed-assemble`。
   - **提示词翻新（现成提示词）**：`seed-analyze` 意图理解 → 交用户确认 → `seed-gen` → `seed-assemble`。
   - **执行方式**：逐环节读取对应模块的 SKILL.md（如 `../seed-express/SKILL.md`）并按其契约在当前对话执行；当前环境提供 Task/Agent 派发工具时，可把环节派发到独立子上下文执行、收回产物后续链（产物与纪律等价）；需与用户多轮往返问答的环节在当前对话执行。探测不到派发工具时不派发、不报错、不阻塞。
5. **中间产物只活在对话**：干净表达、意图理解、缺口清单、已确认结论/共识、构建方案、种子核心、工具清单——全部只在对话内流转，绝不写进最终交付的代码块（链内意图理解尤其不进交付）。
6. **交付唯一**：生成链的产出只有一件——完整结构化提示词，置于代码块中便于复制。不输出过程痕迹（改动对照、改动依据、整理过程、总结），不把任何中间产物当交付物。
7. **交付即止**：交付后不自动开工，也不自动跑质检——全链路结束不触发提示词检查，质检由 /seed-check 命令或用户点名触发（点名时交由 `../seed-check/SKILL.md` 处理）。用户补充信息或要求修改时，从受影响的环节重走，不全链重跑。

## 内部纪律（执行但不输出）

- **交付纯净自检**：交付物里只有提示词——过程痕迹（改动对照、依据、整理过程、总结）等内部检查项，以及各模块中间产物，一律不在。
- **不代行、不改写**：每个环节按对应模块的契约执行；编排器不代各模块补规则、不改写其产物，交付的提示词就是链尾装配环节产出的原样。
- **模块纪律归模块**：可回指、信息零丢失、三大病灶自检等纪律在各模块契约内执行，编排器只核验交付物未混入中间产物与过程说明。

## 禁止事项

- 正例、反例不得写入本技能的任何文件，也不得以过程痕迹（改动对照、依据、整理过程、总结）等形式输出。用户明确要求写入其提示词的内容属用户意图，不受此限。
- 不复述各模块的规则细节——本文件只串链；环节规则以对应模块的 SKILL.md 为准。
- 链内不自动质检；交付后不自动开工；交付物不含中间产物、过程说明与体检报告。
- 不设提问次数、篇幅、Token 等硬性指标（对自身产物的硬指标即元层面过约束）。
- 不做评测、进化、经验沉淀——那是平台循环的职责。
- 编排器自身不调用外部服务、不执行脚本（各模块的可选能力以该模块契约为准）。
