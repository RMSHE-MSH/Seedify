# seed-tools（工具挑选）

按澄清后的需求（想搭什么环境：开发/写作/创造），从插件、skill、MCP 连接器中挑选候选，产出结构化推荐的**两版清单**——对话版（排练期供你判断取舍）与交付版（供装配进【环境与工具】）。全部产出是两份清单本身，不产出交付用提示词（归 seed-gen / seed-assemble）。

## 运行步骤

1. **先读思想纲领**：读取 `references/charter.md`，领会核心思想后再动手。任何产出不得违背该纲领。
2. **取需求与边界**：取调用参数或触发上下文中澄清后的需求（想搭什么环境、要做什么事）。上下文中确无需求时，才用一行话索要。只依据拿到的需求挑选——需求本身含糊或缺关键信息时，不代为澄清（澄清归 seed-clarify），按现有信息只挑有把握的（宁缺毋滥），并把疑问交回澄清环节。
3. **按三层信息源收集候选**（逐层降级，零硬依赖）：
   - **第一层·本地已装清单**：harness 自省当前会话可用的 skills、plugins、MCP 连接器——已装的优先，装了就能直接启用；
   - **第二层·模型知识**：本地清单不足的部分，用模型知识补候选；
   - **第三层·可选增强**：技能目录检索、网络搜索——**仅在用户已启用且允许时**使用；未授权、断网、探测不到可用检索工具时，直接跳过本层，不报错、不阻塞，以前两层继续；绝不因第三层缺失而中断流程，也不虚构检索结果冒充第三层。
4. **筛选候选（宁缺毋滥）**：逐条对照需求约束筛选，只留与需求直接相关、确有把握的候选；不为凑清单而推荐，凑不出像样的清单时宁可出短清单或空清单。
5. **出对话版清单**（对话内呈现，供你判断取舍）：每条含六字段——**名称 / 类型（插件·skill·MCP）/ 为什么是它 / 如何启用 / 来源 / 把握度**。来源=该条出自哪一层信息源、在何处核验；把握度=对这条推荐的把握程度，如实标注（第三层未用时，把握度按前两层证据如实评）。**每条都必须有来源与把握度，缺一不入清单。**「为什么是它」写推荐理由——理由属清单本身。
6. **出交付版清单**（供装配进【环境与工具】）：每条含四字段——**名称 / 类型 / 为什么是它 / 如何启用一句话**。来源与把握度是排练期元信息，**一个字也不进交付版**；「如何启用」压成一句话。
7. **收束**：同时呈现两版清单，交回编排器或供点名下一环节。本模块到此为止，不装配提示词。需求补充或改口时，从受影响的步骤重走。

## 内部纪律（执行但不输出）

- **可回指**：每条推荐都能回指到需求中的哪条约束、以及哪一层信息源；找不到需求依据或信息源依据的候选，不得写入任何一版清单。
- **信息零丢失**：需求中的每条约束（平台、场景、用途、偏好等）在筛选时逐条对照，不静默丢弃任何一条；某条约束无匹配候选时如实说明，而不是当它不存在。
- **三大病灶自检**（按 M4 职责）：不臆造不存在的工具；不堆砌——宁缺毋滥，不为凑数推荐无关项、不把一个工具拆成多条充数；不把猜测写成事实——把握度低的候选如实标注，模型记忆不冒充已核验事实，第三层没跑就说没跑。
- **两版分界**：来源与把握度只活在对话版；交付版物理上不出现这两个字段。
- **三层降级**：第三层只在用户启用且允许时使用；不可用即降级到前两层，不报错、不阻塞、不虚构检索结果。

## 禁止事项

- 只做工具挑选：不做表达整理（归 seed-express）、不做需求澄清（归 seed-clarify）、不做种子成文（归 seed-gen）、不做装配（归 seed-assemble）、不做意图解读（归 seed-analyze）、不做质检（归 seed-check）。
- 不产出交付用提示词——本模块产出只有对话版与交付版两份清单。
- 交付版恰好四字段（名称/类型/为什么是它/启用一句话）；来源、把握度等排练期元信息只在对话版。
- 正例、反例不得写入本技能的任何文件，也不得作为说明性内容输出。
- 不设清单条数、篇幅、Token 等硬性指标（宁缺毋滥不是"必须凑够 N 条"）。
- 不执行脚本、不调用外部服务；网络检索仅发生在用户启用且允许时，否则降级不报错、不阻塞。
