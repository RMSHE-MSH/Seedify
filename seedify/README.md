# seedify（种子化）

把带转写噪声的口语输入，保真整理、问清疑问，自主生成种子提示词——只交付提示词本身。

提示词是种子，不是蓝图；优化是进化，不是润色。

**当前版本 v0.2.0**：七模块（M1–M7）+ 编排器 + 8 条命令。

## 它做什么

**生成族 + 读取族两条能力轴**：生成族（M1 表达整理 → M2 需求澄清 → M3 种子生成 → M4 工具挑选 → M5 提示词装配）把带转写噪声的口语输入整理、问清、装配成一份可直接粘贴进新会话的结构化种子提示词；读取族（M6 提示词分析 / M7 提示词检查）对任意现成提示词做意图解读与纲领体检。

两条轴共用一套纪律：

1. **保真整理**：把已说的说清楚，未说的不添加，有歧义先问（有疑必问、开放问法、不限次数）；
2. **种子自然生成**：目标、硬边界、验收三要素只作提示不设栏位，用户说到多少写多少；不写实施方法（流程、步骤、角色、示例、格式）；
3. **交付即止**：只给出提示词（代码块），不输出改动对照、依据、整理过程与总结，不自动开工——执行循环与经验沉淀归 Claude Code / 桌面版 / cowork 的平台机制。

## 安装

**Claude Code**（一步安装，2.1.275+）：

```
/plugin install seedify --marketplace <本仓库克隆路径>
```

或命令行等价：

```bash
claude plugin marketplace add <本仓库克隆路径>
claude plugin install seedify@seedify
```

临时加载（开发试用）：

```bash
claude --plugin-dir <本目录路径>
```

若要把本插件纳入自己的 marketplace 分发：在市场的 `marketplace.json` 中列入本插件后，`/plugin marketplace add <该市场>` 再 `/plugin install seedify`。

**Claude 桌面版**：插件安装方式同上；或将 `seedify/skills/` 下各技能目录作为技能安装（每个技能的 `references/` 子目录须完整保留）。

**cowork**：在应用内上传项目根的 `seedify-skill-cowork.zip`。随包是全部 8 个运行时技能（7 个 mod + 编排器）的 `SKILL.md` 与 `references/`；cowork 是独立体系（不读 `~/.claude`），`commands/` 与 `agents/` 不随行——命令入口在 cowork 不可用，请直接用技能或自然语言触发；探测不到可派发子代理时，M7 由 seed-check 技能自身执行，独立性弱化属已知局限。

## 命令梯子

单模块 → 组合子链 → 一键全链路，按需取用（组合子链靠相邻命令先后接力，中间产物只活在对话里）：

| 命令 | 层 | 用途 |
|---|---|---|
| `/seed-express <文本>` | M1 | 只优化表达 |
| `/seed-clarify <主题或现状>` | M2 | 追问 / 头脑风暴 / 流程体检（按输入自动判断，可点名模式） |
| `/seed <文本>` | M3 | 只生成种子提示词 |
| `/seed-tools <需求>` | M4 | 只出工具推荐清单 |
| `/seed-assemble [材料]` | M5 | 装配成最终提示词（无参则取本次对话已有的各环节产出） |
| `/seed-analyze <表达或提示词>` | M6 | 只做意图解读（任意表达/现成提示词 → 意图理解） |
| `/seedify <原始文本>` | 全链路 | 一键一条龙：表达整理 → 意图理解 → 需求澄清 → 种子生成 → 工具挑选 → 装配 |
| `/seed-check <提示词>` | M7 | 提示词检查：分项通过 + 合格判定 + 纪律符合度总结分（派发独立评审，只诊断不改写） |

**语义变更（v0.1 → v0.2）**：`/seed` 曾是准全链路入口，自 v0.2 起收窄为**纯种子生成**，全链路迁至 `/seedify`；`/seed-check` 自 v0.2 起增加合格判定与纪律符合度总结分。

**自然语言触发**（含语音转写错字变体，按读音与语义匹配，不必逐字精确）：

- 全链路："帮我优化提示词 <原始文本>"、"优化提示词 <原始文本>"、"提示词种子化 <原始文本>"、"整理我说的话 <原始文本>"
- 两个时刻："预演/预热一下开工提示词"、"帮我看清方向"
- 单模块与体检：点名环节（如只要表达整理、只要意图解读、只要工具清单）即单模块执行；"检查/体检一下这段提示词"即走 M7。

## 两个使用时刻

- **时刻 A · 开项目**：开新项目/新会话前，把最初的想法和思路捋出来、搭好开场提示词与开场环境，定稿后再正式开工——走 `/seedify` 全链路，交付可直接粘贴的结构化种子提示词；
- **时刻 B · 中途迷路**：项目走一步看一步、思绪乱掉时，头脑风暴找出方向与 idea、引导挑选，再把谈出来的东西沉淀回提示词——`/seed-clarify` 起步，挑定方向后按需经 `/seed-express`、`/seed` 再 `/seed-assemble` 装配。

**提示词翻新**（读取族 → 生成族的组合，非新模块）：对一份现成提示词（自己写的或别人写的），`/seed-analyze` 先解读它在要什么 → 用户确认意图 → `/seed` 重做种子 → `/seed-assemble` 装配成新的提示词。

## 评分说明

`/seed-check`（M7）输出：分项通过/不通过 + 问题清单 + 合格判定 + 纪律符合度总结分。总结分**只度量纲领纪律符合度，不预测实践效果**——报告必附这句声明；合格 = 纲领病灶项全部通过（零病灶），缺失/疑点分列标注、不判否（种子本就"说到多少写多少"）。

分数不作优化目标、不作交付门槛；评分不因"详细、结构完整、有示例"而加分——通用的"好提示词"标准奖励的恰是纲领病灶。体检只诊断不改写；要改写须另行发起、走生成族。

## 纲领指引

- 思想纲领（最高指导）：总纲 v4 原文入包于每个技能的 `references/charter.md`，运行前先读；单一事实源在插件目录之外的 `../docs/prompt-optimization-charter.md`（用户定稿，我方不得改动）。
- 设计文档：`../docs/seedify-mod-design-v1.md`（模块化设计 v2，已审定）、`../docs/seedify-design-v1.md`（v6）——位于插件目录之外，不随插件分发。
- 开发期护栏 T1–T27 清单在 `skills/seedify/references/anti-patterns.md`（开发期资产，运行时不读取）。
- 无外部依赖、无脚本，Hooks/MCP/Settings = 0；正例、反例一律不进技能上下文（触发短语与调用示例除外），避免少样本锚定。
